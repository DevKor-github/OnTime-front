# [P2][U05] 설정·준비·결과·백업·복구와 native 활성 경로의 한국어·영어 혼입을 없앤다

## 문제와 사용자 영향

OnTime은 KO/EN을 지원하지만 영어로 실행해도 알림 설정의 loading/off/error, 준비 중 남은 시간, 결과 응원 문구, 초기화 완료·복구 안내에 한국어가 남는다. 반대로 한국어 화면에 영어 고정 AM/PM과 native 버튼·권한 설명이 남을 수 있다. 같은 일정 시각을 24시간 숫자 뒤 AM/PM으로 중복 표현하거나, 첫 OS 선호 언어만 읽는 알림과 전체 선호 언어 목록을 해석하는 앱의 언어가 달라지는 경로도 있다. 단순 문자열 치환만으로는 이미 Bloc에 저장된 완성 문장, 화면을 연 상태의 locale 변경, DB가 열리지 않는 pre-DI 복구, OS에 예약된 문구를 해결하지 못한다.

목표는 **동일한 데이터·작업·상태를 유지하면서 앱이 소유한 문구를 실제 해석된 KO/EN 언어와 시스템 시간 표시 선호에 맞게 보여 주는 것**이다. 사용자가 작성한 일정·장소·준비 이름은 번역하지 않는다. 로컬 전용 Android/iOS 앱이라는 제품 경계, 알림 개인정보 보호, 일정 시각/기간 계산과 저장·복구 동작은 바꾸지 않는다.

- 우선순위: **P2 / 감사에서 확인된 결함**. 영어 사용자의 설정·복구·실패 안내 이해에 영향을 준다. 데이터 무결성·저장/알림 소유권 선행 P0/P1을 먼저 처리한다.
- 설계 상태: 전담 subagent `/root/grill_u05`가 `grill-with-docs`를 읽고 조사, root가 사용자 대신 순차 질문에 답한 **설계 완료 / 구현·실행 검증 전**이다.
- 고정 근거 SHA: **`fb874a4c5d174ba9ae4df6e22ceb6bf92e6da49f`**. 아래 GitHub source 링크는 모두 이 commit이다. 같은 workspace의 A08 제품 WIP와 혼동하지 않는다.
- A08 WIP에는 새 typed 저장 실패·receipt와 KO/EN 문구가 추가 중이다. 고정 commit의 ARB는 EN/KO 각각 **203개 메시지 키**이며 조사 시 WIP는 각각 212개였다. 이 숫자는 완성도 지표가 아니며 구현 착수 시 최종 source를 다시 inventory해야 한다.
- 이번 조사에서 Flutter·test·codegen·native 빌드를 실행하지 않았다. 소스 확인과 기존 테스트 목록 확인만 수행했다. 실제 KO/EN 렌더·기기 성공을 주장하지 않는다.

## 확정 계약

### 1. catalog와 도메인 언어

- `lib/l10n/app_en.arb`가 template인 기존 구조를 사용한다. KO/EN 완성 문장, typed placeholder, 필요한 plural을 둔다. 조각을 조합해 한국어 조사·영어 어순·단복수가 틀어지지 않게 한다. 의미가 다른 메시지를 키 수를 줄이려 억지 통합하지 않는다.
- 앱 소유 사용자 문구의 Dart inline KO/EN 분기와 하드코딩을 ARB 중심으로 정리한다. native는 해당 플랫폼의 실제 bundle localization 형식을 사용한다. Dart ARB를 native UI가 직접 읽도록 억지로 연결하지 않는다. 앱/알림의 의미·언어 해석·번역 목록은 일치시킨다.
- domain/Bloc의 상태는 stable failure/status/message 식별자와 타입 있는 인자를 보존한다. UI 또는 적절한 platform adapter가 현재 resolved language에서 렌더한다. BuildContext, 번역용 DB 읽기, 원격 번역 호출을 domain에 넣지 않는다.
- 응원 문구의 구간·무작위 선택·이미지 연결은 기존 제품 의미를 유지하고 선택된 ID를 한 번 보관한다. locale 변경/일반 rebuild로 다시 선택하지 않는다. 모든 ID와 fallback에 KO/EN 문구가 존재해야 한다.
- `CONTEXT.md`의 Schedule, Preparation Step, Preparation Duration, Schedule Spare Time, Local Profile, Schedule Notification, iOS AlarmKit Alarm을 따라 문구를 구별한다. 로그인/서버 계정이 없는 앱에 account 복구를 새로 암시하지 않는다. 준비/이동/여유 시간을 번역 과정에서 합치지 않는다.
- [ADR 0009](https://github.com/DevKor-github/OnTime-front/blob/fb874a4c5d174ba9ae4df6e22ceb6bf92e6da49f/docs/adr/0009-use-alarm-language-only-for-ios-alarmkit.md), [로컬 전용 ADR 0011](https://github.com/DevKor-github/OnTime-front/blob/fb874a4c5d174ba9ae4df6e22ceb6bf92e6da49f/docs/adr/0011-make-ontime-local-only.md), [시간대 ADR 0021](https://github.com/DevKor-github/OnTime-front/blob/fb874a4c5d174ba9ae4df6e22ceb6bf92e6da49f/docs/adr/0021-anchor-schedules-to-a-named-time-zone.md), [private 알림 ADR 0030](https://github.com/DevKor-github/OnTime-front/blob/fb874a4c5d174ba9ae4df6e22ceb6bf92e6da49f/docs/adr/0030-default-to-private-notification-content.md)을 따른다. 새 도메인 용어·되돌리기 어려운 아키텍처 결정이 없으므로 이번 설계에서 CONTEXT/ADR을 추가하지 않는다.

| OS preferred locales | 현재 정책에 따른 effective locale | 회귀 목적 |
|---|---|---|
| `[fr, ko]` | `ko` | 첫 unsupported 언어만 보고 알림을 EN으로 만드는 분기 제거 |
| `[fr, en]` | `en` | 두 번째 지원 언어 선택 |
| `[fr]` 또는 모두 미지원 | 첫 지원 locale `en` | unsupported fallback을 별도 임의 언어로 바꾸지 않음 |
| `[]` / 초기 preferred 목록 없음 | 첫 지원 locale `en` | pre-DI/cold-start 안전 fallback |
| `[ko_KR]` | 지원 `ko` | language match |
| `[en_US]` | 지원 `en` | language match |

locale 변경은 draft, validation 원인, 실행 시간/체크 상태, save/restore/reset operation, receipt identity, 선택된 응원 ID/이미지를 초기화하지 않는다. 번역 문자열을 새로 렌더하되 DB content revision·backup freshness를 dirty로 만들지 않는다. locale 변경 중 늦게 도착한 비동기 결과도 원래 작업의 소유권/현재성에 따라 처리한다. 번역을 얻으려고 DB를 다시 열거나 reset을 다시 실행하지 않는다.

### 3. 시각과 기간

- 날짜/요일/표시 숫자·단복수는 실제 resolved KO/EN을 사용한다. 하루의 시각은 기존 Schedule Time Zone에서 변환된 civil time을 `MaterialLocalizations`와 `MediaQuery.alwaysUse24HourFormat`으로 표시한다. 24시간 요청을 존중하고 그 외에는 해당 locale 기본 형식을 따른다. 24h 숫자 뒤 AM/PM을 별도 붙이지 않는다.
- 이미 계산된 instant/time-zone/DST ambiguity 선택을 바꾸거나 locale에 따라 다른 날짜·시각을 저장하지 않는다. 표시는 civil time이고 정렬·실행 판단은 기존 데이터 계약을 그대로 따른다.
- 경과/남은 **기간**에는 12/24h 형식을 적용하지 않는다. `00 : 00`/시간 포함 timer는 기존 표시를 유지하되 접근성 읽기 단위는 KO/EN으로 제공한다. 1시간을 하루의 1시로 바꾸거나 24시간 이상을 wrap하지 않는다.
- U04 [#625](https://github.com/DevKor-github/OnTime-front/issues/625)의 결과 기간 `abs + 초 버림 + 0~59초=0분`, 정확한 1/2시간 수정 및 기존 localized helper 재사용을 보존한다. 준비 `formatTime`/`formatElapsedTime`의 현재 반올림·초 생략 정책과 결과 메시지 선택의 ceil은 서로 다르므로 일괄 통일하지 않는다.

### 4. 오류·복구·백업

Known typed 실패를 그 의미에 맞는 KO/EN 문장으로 렌더한다. 재시도 가능한 저장 실패, stale preview, DB 반영 전 실패, 반영 후 알림 정리 미확인, reset pending/일부 삭제/완료를 구별한다. unknown exception은 안전한 일반 메시지로 표시하고 SQL·파일 경로·native localizedDescription·비밀번호·사용자 입력 전체를 노출하지 않는다. 로그 정책도 완화하지 않는다.

pre-DI 복구는 기존 복구 MaterialApp의 bundled localization을 사용한다. DI/DB가 불가능한 상황에서 resource를 렌더하려 DI/DB를 다시 열면 안 된다. locale 변경 중에도 “데이터가 보존됨/이미 삭제됨/정리가 미확인됨”이라는 실제 receipt 의미가 바뀌지 않는다. OS 파일 picker 취소는 오류/성공으로 잘못 바꾸지 않으며 OS가 표시하는 provider 문구는 OS 언어 관찰로 별도 기록한다.

### 5. 알림·native 경계

- 앱과 동일한 지원 언어/선호 목록 해석을 platform adapter에서 재사용한다. active, cold start, 복구 경로와 알림 생성에서 서로 다른 첫-locale shortcut을 쓰지 않는다. 현재 domain language provider의 플랫폼 접근은 최소 adapter 주입으로 정리하되 광범위 아키텍처 변경을 하지 않는다.
- A05의 `ScheduledNotificationContent` normalized language + content digest와 기존 desired/existing 비교, A15 owner를 사용한다. 다음 정상 reconcile에서 현재 pending 알림의 옛 언어 차이를 감지하여 안전한 대상만 갱신한다. 시각/ID가 같다고 옛 언어를 영구 재사용하지 않는다. 새 locale watcher/retry/reconciliation 엔진을 만들지 않는다.
- 이미 표시된 OS 알림의 언어가 즉시 바뀐다고 보장하지 않는다. platform별 한계와 다음 생성/기존 reconcile 반영 시점을 명시한다. provider 완료가 locale 변경보다 늦게 돌아오면 old completion이 최신 locale의 delivery를 확인한 것처럼 표시되지 않도록 A15의 최신 요청/후속 reconcile 회귀를 재사용한다.
- 상세 알림 OFF에서 일정/장소/준비 본문을 노출하지 않는 A11 경계, 최소 routing payload/A12, A15 ownership을 그대로 유지한다. 번역용으로 raw payload를 추가하거나 digest 대신 원문을 fingerprint/로그에 기록하지 않는다.
- 앱이 소유한 iOS usage description/AlarmKit 버튼/접근성, Android 활성 notification 채널·버튼/접근성 문구를 번들에 포함한다. iOS AlarmKit은 실제 build/device capability를 전제로 하고 fallback은 notification 용어다. 미활성 Android full-screen 경로는 현재 reachability와 제외 근거를 기록한다. 문구 수정을 위해 권한·full-screen 정책을 활성화하지 않는다.
- OS permission dialog의 시스템 부분, OS settings, OS 파일 provider를 앱이 강제 번역하지 않는다. native 앱 소유 부분과 OS 소유 부분을 실제 기기에서 구별해 관찰한다.

## 구현 순서와 검증 산출물

1. 구현 착수의 정확한 SHA·선행 PR 상태를 읽고 A08/C01/D03/U04 최종 소스 기준 inventory를 갱신한다. 현재표와 차이를 남긴다. 각 제외 항목은 reachability/OS 소유/사용자 입력/정책 승인 대기 근거가 있어야 한다.
2. 실패·상태·응원 문구 stable ID/typed 인자와 presentation 렌더를 연결한다. 기존 domain 타입을 재사용하고 locale용 상태 엔진을 추가하지 않는다. ARB complete sentence/placeholder/plural, active native 리소스를 추가한다.
3. 실제 효과 locale 해석을 앱과 알림 adapter가 공유하게 하고 기존 digest/owner로 다음 정상 reconcile 언어 갱신을 검증한다. 날짜/요일/시각 formatter 소비 지점을 정리하되 원래 데이터 변환과 기간 계산은 유지한다.
4. 실제 앱 위젯에서 negative→positive 증거를 남긴다. 예: 영어 설정에서 한국어 off 상태, 영어 준비 상단, 한국어만 있는 결과/복구 화면, 24h+AM/PM 중복, 첫 미지원+둘째 KO에서 알림 EN 불일치. 이미 올바른 ARB helper 단위 테스트만 실행해 소비자 연결 누락을 숨기지 않는다.
5. key/placeholder/plural 및 실제 locale 전환·typed 오류·알림 privacy 회귀를 수행한다. 의미 없는 구현 mirror test·전체 복제 fixture 대신 기존 workflow/receipt/fault tests에 locale assertion을 연결한다. matrix별 명령·결과·미실행 사유를 남긴다.
6. `flutter gen-l10n` 등 저장소에서 사용하는 정식 generation과 필요한 build_runner를 실행하고 `flutter analyze`, 관련 unit/widget/native 검사 및 변경 영향에 맞는 전체 suite를 수행한다. tracked `lib/l10n/app_localizations*.dart`는 ARB와 함께 반영하고 ignored `*.g.dart`, `*.config.dart`, `*.freezed.dart`, `*.mocks.dart` 등은 commit하지 않는다. 분석과 test 성공만으로 native 동작을 증명하지 않는다.
7. KO/EN 작은 화면·200%/Semantics 증거와 실제 Android/iOS 활성 native 리소스/권한 문구 관찰을 source SHA·artifact hash·locale·OS/device 조건에 묶는다. 기존 T01/T02 RC 검증을 재사용하며 미실행 native 조건은 issue OPEN에 남긴다. 번역 승인이 안 된 정책은 O02 pending으로 정확히 남긴다.
