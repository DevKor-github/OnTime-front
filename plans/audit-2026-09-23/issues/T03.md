## 문제와 책임

테스트가 없다는 문제가 아니다. 실제 sodium 테스트, profile rollback, 복원과 알람 취소의 경쟁, reset journal 복구 및 host 강제 종료 검증이 이미 있다. 공백은 **제품의 실패 경계와 실제 확보한 증거를 연결하는 공통 행렬**, 그리고 각 작업을 함께 수행할 때의 보존·부분 완료·재시도·세대 교체 증거다. 단순 mock 반환과 호출 횟수, 총 테스트 개수, 전체 coverage만으로 데이터 보존이나 원자적 교체를 증명할 수 없다.

T03은 각 기능의 테스트를 별도 프레임워크로 복제하지 않는다. A04/A07/A08/A09/D01–D05가 소유하는 제품 수정과 그 이슈의 필수 회귀를 그대로 연결하고, **남은 교차 workflow 실험과 재현 가능한 증거**를 추가한다. 테스트에서 실제 결함을 발견하면 원래 제품 이슈에 연결해 수정하며, 구현의 잘못된 현재 행동을 기대값으로 고정하지 않는다.

Android/iOS local-only와 기존 schema 2, payload format 1/2, crypto envelope version 1, Preparation Run·Backup Restore·Recovery Mode·Local Data Reset 계약을 유지한다. 서버, 원격 장애 복구, 로그인, cloud test analytics를 추가하지 않는다.

## 도메인 판정 기준

[CONTEXT](https://github.com/DevKor-github/OnTime-front/blob/204804e32e1c5f741b3d5644698cd3dde3502592/CONTEXT.md), ADR 0013/0023/0026/0028/0029/0031/0032 및 [ADR0036 active pair](https://github.com/DevKor-github/OnTime-front/blob/204804e32e1c5f741b3d5644698cd3dde3502592/docs/adr/0036-select-recovery-store-and-key-as-one-active-pair.md)를 따른다. 여기서 commit 경계·fault point·evidence level은 검증 설명이며 새 제품 용어가 아니다. 새 glossary/ADR는 필요하지 않다.

- **commit 이전 실패**: 작업의 소유 범위에 대한 durable 상태가 바뀌지 않았음을 실제 read-back한다. 준비 시작 실패면 화면/버튼과 같은 의도 재시도도 확인한다. 미리 수행한 delivery cleanup이 있다면 그것을 ‘아무 부작용도 없었다’고 숨기지 않고 원래 기능의 복구 계약을 검사한다.
- **commit 이후 후속 실패**: 이미 확정된 시작/복원/삭제 사실을 실패 반환만 보고 rollback이라고 표시하지 않는다. typed partial/pending과 필요한 단계만 재시도하는 계약을 확인한다.
- **애매한 응답**: write가 오류를 반환하거나 receipt가 없어도 독립 read-back에 확정된 사실이 있으면 그 사실을 따른다. 단순 예외 유무는 저장소의 oracle이 아니다.
- **재시도 수렴**: 같은 service/의도에서 재시도, 새 instance에서 재개, 실제 새 process에서 재개를 구별한다. 한 번의 의도가 중복 row/revision/run/navigation/OS 등록을 만들지 않고 최신 committed 결과로 수렴해야 한다.
- **세대 전환**: reset/restore 이후 같은 ID를 가진 새 데이터에 이전 Future/flight/snapshot/notification 결과가 적용되지 않는다. Future를 무시했다고 실제 native 작업이 취소됐다고 주장하지 않는다.
- **보존 관측**: durable rows/관계·schema/version·revision·runtime generation·active pair·비노출 key identity·registry/journal ownership·사용자 화면을 해당 경계에 맞춰 함께 본다. SQLite/WAL 파일 전체 byte hash 동일을 모든 rollback의 조건으로 삼지 않는다.
- **비밀 보호**: 합성 fixture만 사용한다. raw 비밀번호·키·복호문·사용자 note/payload·실제 경로가 예외/UI/log/artifact에 노출되지 않았음을 확인한다. 디버그 편의를 위해 원본 정보를 로그에 더하지 않는다.

## 암호문·parser 실험 행렬

직접 만든 암호 primitive나 fake crypto 성공값으로 인증을 검증하지 않는다. 실제 sodium과 공개 제품 경로를 사용한다. header/frame를 변형하는 테스트 helper는 container 구조를 읽고 입력을 만드는 도구이며 별도의 decrypt 구현이나 성공 oracle이 아니다.

비싼 KDF를 모든 변형마다 다시 생성할 필요는 없다. 검증된 합성 encrypted fixture를 재사용하고 동일 속성 동치군을 표본화할 수 있으나 행렬과 실제 case의 매핑을 남겨 누락을 숨기지 않는다. KDF 이전 거부는 loader/derive boundary의 spy wrapper로 관측할 수 있으나 유효한 지원 입력의 암호학적 실패는 실제 sodium을 사용한다. fuzz/property를 도입하면 고정 seed·bounded 실행·최소 실패 fixture·재현 명령을 기록하며 무한 fuzz나 통과할 때까지 재실행하지 않는다.

D05의 72 MiB ciphertext, 64 MiB plaintext, depth 32, schedule 100,000/total 500,000 records, steps 1,000, work budget 2,000,000 및 하위 문자열/숫자 규칙을 이 이슈에서 재정의하지 않는다. 실제 모바일 peak memory/시간의 증명은 별도 모바일 증거다. 작은 주입 한도 테스트만으로 제품 상한에서의 실제 메모리 동작을 통과로 보고하지 않는다.

## 증거와 실행 방식

1. 각 행에 제품 이슈·현재 구현 상태·test path/name·fixture 출처/hash·source SHA·fault 지점·실제 오류·기대 불변식·결과 artifact·남은 한계를 기록한다. 상태는 기존 증거 충족/추가 실험 필요/제품 의존 미구현/실행 실패/모바일 미검증을 구별한다.
2. 동일 프로세스 adapter fault, 실제 SQLite 오류, fresh-instance, host SIGKILL, Android/iOS 재실행을 별도 증거 수준으로 표기한다. native mock 또는 plain SQLite 성공을 SQLCipher·실제 OS 성공으로 부르지 않는다.
3. 실패 전후 실제 저장소를 읽는다. logical rows/schema/version/revision 및 비노출 key identity가 oracle이다. fixture/hash는 재현성과 입력 보존을 위한 것이며 WAL/checkpoint에 따른 물리적 바이트 차이를 논리 rollback 실패로 오인하지 않는다.
4. 동시성은 Completer/latch·제어 clock·해당 단계 read-back으로 도착 순서를 정한다. 임의 sleep에 의존하지 않고 bounded watchdog은 hang을 실패로 보고한다. timeout 자체로 취소·commit/rollback·owner 해제를 추정하지 않는다.
5. host kill은 자체 생성한 temp 디렉터리와 자식 프로세스만 종료한다. D03의 완료 checkpoint 11개를 기반으로 D02 active pair와 D04 migration의 새 경계만 추가한다. 기존 사용자 DB·키·부팅된 simulator·기존 앱 데이터를 사용하지 않는다.
6. synthetic fixture에 정상/오류 구조, version, source provenance를 남긴다. 역사 fixture는 현재 serializer가 만든 자료만으로 대신하지 않는다. 비밀번호/키는 테스트 전용이며 artifact에 원문을 내보내지 않는다.
7. 빠른 결정적 회귀는 기존 `flutter test`/PR CI에 포함한다. 지원 runner에서 host kill은 명시 job/명령·timeout·로그·result를 제공한다. CI wiring은 T01/R 관련 이슈, 모바일 반복 실행 기반은 T02와 연결하고 중복 workflow/framework를 만들지 않는다.
8. 전체 실행 SHA와 CI run/check 결과를 새로 기록한다. 선행 D03 872/host11이나 A06 결과를 다른 source에 재사용하는 경우 변경 영향과 한계를 표시한다. 실패 후 임의 skip/pass, 과도한 retry, coverage threshold 완화로 결과를 바꾸지 않는다.
