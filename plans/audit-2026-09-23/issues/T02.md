## 공식 근거와 읽기 한계

- [Flutter 테스트 개요](https://docs.flutter.dev/testing/overview)는 integration_test가 native permission dialog·notification 같은 UI를 조작하지 못한다고 명시한다. Flutter tree 밖의 조작은 native driver/명시 기기 절차가 필요하다. 문서는 현재 버전 기준이므로 이슈가 locked Flutter 3.44.4를 자동 업그레이드하라는 뜻은 아니다.
- [Android instrumented tests](https://developer.android.com/training/testing/instrumented-tests)와 [UI Automator](https://developer.android.com/training/testing/other-components/ui-automator)는 기기/에뮬레이터에서 플랫폼 및 시스템 UI를 실행할 경로다. 현재 문서의 alpha 예제를 그대로 추가하지 않고 locked Gradle/SDK와 호환되는 runner를 선택·고정한다.
- [Android notification permission](https://developer.android.com/develop/ui/views/notifications/notification-permission)은 API33+ POST_NOTIFICATIONS 권한 분리를, [alarm 문서](https://developer.android.com/develop/background-work/services/alarms)는 exact 권한·실제 OS 동작 경계 검토를 뒷받침한다. API/target별 정확한 동작은 설치한 artifact와 실행 OS로 판정한다.
- [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files)는 시스템 document picker 및 content URI 경계의 공식 근거다. [SQLCipher API](https://www.zetetic.net/sqlcipher/sqlcipher-api/)는 cipher 확인과 실제 엔진 계약의 참고다. PRAGMA 실행·단일 엔진 검사만으로 전체 보안 감사를 완료했다고 주장하지 않는다.
- Apple [XCTest](https://developer.apple.com/documentation/xctest), [AlarmKit](https://developer.apple.com/documentation/alarmkit), [Keychain 접근성](https://developer.apple.com/documentation/security/ksecattraccessibleafterfirstunlockthisdeviceonly), [export-as-copy](https://developer.apple.com/documentation/uikit/uidocumentpickerviewcontroller/init(forexporting:ascopy:)) URL은 확인했다. 본문은 JavaScript 페이지였고 Markdown 응답을 이번 web 도구가 읽지 못했다. 따라서 이 링크를 본문/API 세부사항을 확인한 증거로 쓰지 않는다. 위 iOS 계약은 고정 repo 소스·기존 SDK typecheck 기록에 근거하며 실제 구현/실행 시 SDK와 공식 API 본문을 다시 확인한다.

## 확정한 검증 경계

| 증거 종류 | 증명하는 것 | 증명하지 않는 것 |
|---|---|---|
| 소스·정적 계약 | receiver/권한/entitlement/등록·타입 연결과 금지 정책 | OS가 해당 경로를 실제 호출하거나 전달했다는 사실 |
| release artifact 검사 | 실제 packaged manifest·라이브러리/설정 및 artifact identity | 설치·권한 수락·실제 수신 또는 store 서명 |

| emulator/simulator 플랫폼 실행 | 명시 runtime의 서비스/스토리지/UI 동작 | 물리 secure hardware·잠금/재부팅·OEM 동작 전체 |

1. 기존 manifest·native 컴파일·Dart contract를 유지하고 실제 native 실행을 추가한다. 유효한 RunnerTests를 다시 placeholder 취급하거나 단순 test 소스 존재를 실행 결과로 표시하지 않는다.
2. T02의 native contract는 실제 앱 plugin 등록과 메서드 이름/argument/result 계약을 통과해야 한다. 순수 parser 단위 테스트를 유지할 수 있으나 모든 결과를 fake 성공으로 채운 suite만으로 끝내지 않는다.
3. 정상 OS 행동은 실제 provider/권한/파일을 관측한다. 의도적으로 주입한 provider 실패, mock callback, fake clock은 사용 사실과 제한을 별도 기록한다. T03의 실제 장애 증거와 서로 바꿔 부르지 않는다.
4. source SHA와 CI merge SHA를 구별하고 실제 설치한 APK/IPA의 digest·서명종류를 기록한다. 이전 검증 artifact와 다른 로컬 build를 같은 것으로 취급하지 않는다. validation key build는 store candidate가 아니다.
5. 실패 후 무제한 재시도·조건 삭제·silent skip으로 green을 만들지 않는다. finite watchdog 초과는 실패/환경 blocked이며 반환하지 않은 실제 OS 작업의 owner를 해제해 새 작업을 겹치지 않는다. 지연 반환과 원 실패·후속 결과를 모두 기록한다.
6. 테스트 fixture는 합성 데이터만 사용한다. 키 값·비밀번호·production DB·복호화한 실제 사용자 원문·서명 비밀은 로그/스크린샷/artifact에 넣지 않는다. SQLCipher 동작 검증을 암호학적 안전성 전체의 보증으로 확대하지 않는다.

## OS 대표 행렬과 격리

경계별 대표 실행으로 구성하며 모든 OS×기기×권한의 무한 곱집합을 만들지 않는다. 동일 실제 실행이 여러 행을 입증하면 하나의 evidence ID를 재사용한다. build-only와 실행을 분리하고, 하한 runtime을 구할 수 없으면 그 행을 pending으로 남긴다.

- runner는 자기 소유의 disposable AVD/simulator만 생성·선택·초기화·권한변경·종료·정리한다. target ID, 앱 ID, run ID를 명시 검증하고 명령에 고정한다.
- 기존 `C8BA159D-A97A-458B-A5FC-B04A8B6F2848` simulator, 다른 QA 환경, 사용자 기기를 자동 선택하거나 지우지 않는다. 물리 기기는 이후 명시 지정된 QA 대상에서만 합성 fixture로 실행한다. 호스트 네트워크 설정을 바꾸지 않는다.
- 조사 시점 root가 파악한 환경은 Android 연결 없음·물리 iOS unavailable이다. 이 문서 작성에서 기기 탐색/실행을 다시 하지 않았으므로 현재 가용성을 확정하지 않는다. 실행 직전 read-back하여 가용성 manifest를 갱신한다.
- min/target/SDK/OS patch/모델·locale·timezone을 manifest에 고정한다. 새 OS 출시 또는 구 runtime 확보 문제를 이유로 지원 하한/SDK/toolchain을 임의 변경하지 않는다.
- Android ordinary process kill과 Settings force-stop은 다르다. force-stop은 별도 제한 관찰이며 그 상태의 전달 보장을 제품에 추가하지 않는다. OEM QUICKBOOT 선언 검사와 실제 OEM reboot를 구별한다.

## 구현·CI·증거 산출물

1. T02에서 재현 가능한 native test entrypoint, fixture, 실행 manifest, 결과 schema, native UI/수동 절차 및 증거 경로를 둔다. Android instrumented target과 iOS 실제 XCTest 실행을 구성하고 성공·실패 실제 결과를 확보한다. 실행되지 않은 예시 명령을 성공 로그처럼 적지 않는다.
2. 필요한 최소 native driver를 locked 도구와 호환되게 선택한다. Flutter E2E 전체를 새 native suite에 복제하지 않고 T01 native UI bridge를 공유한다. 프로덕션 데이터 export/키 출력용 debug channel을 추가하지 않는다.
3. 기존 Flutter analyze/test/coverage와 Android packaged-manifest CI를 재사용한다. **R02**는 native/mobile build·job 배선, **R04**는 동일 검증소스와 배포 연결, **R01**은 required checks, **R09**는 최종 release artifact/네트워크 경계를 소유한다. T02의 actual native test 결과를 이 경로에 연결하며 compile-only job으로 대체하지 않는다.
4. native contract의 결정적 행은 PR 자동 검사 목표, 오래 걸리는 OS 전이/물리 RC 행은 명시된 release validation 단계로 분리한다. 필수 행을 누락하거나 skipped job을 전체 성공에 합산하지 않는다. CI 연결 전에는 로컬 suite 존재만으로 원격 gate가 적용됐다고 하지 않는다.
5. 결과마다 `caseId`, `sourceSha`, `mergeSha`(해당 시), `artifactDigest`, build mode/version/build, signing 종류, 실제 installed app ID, OS/patch/model/target ID, toolchain/SDK, locale/device/schedule timezone, run/fixture ID, provider/display/timing 권한, lifecycle, expected/actual, 실행 시간, driver/injection, evidence/assertion 경로, `pass|fail|blocked|not_run` 및 사유를 남긴다.
6. XCTest xcresult/JUnit 등 native 원본, 실패 로그, 합성 화면 기록, 실제 파일 digest 및 재시도 전 원 실패를 보존한다. 권한/기기/driver 오류와 제품 assertion 실패를 구별한다. flaky 실패를 덮는 rerun만 남기지 않는다.
7. 테스트 runner가 소유한 임시 데이터·기기만 정리한다. 프로세스 timeout 처리와 제품 OS 작업 owner의 수명을 구별하고, 아직 작업이 살아 있으면 겹치는 재시도를 하지 않는다. 취소 가능한 fixture와 실제로 반환하지 않은 provider를 구분해 teardown도 검증한다.
8. matrix의 필수 native/platform/물리 행과 환경 가용성을 기계적으로 확인할 수 있게 한다. hardware/signing/구 runtime 부재는 구체 행 pending이며 다른 구현은 계속할 수 있지만 이슈 완료는 아니다. 기존 검증 링크의 SHA가 다르면 제한을 명시한다.
