## 확정한 읽기·레이아웃 정책

홈/접힌 요약 카드의 줄임표는 실제 접근 가능한 상세에서 전체 일정 이름과 장소를 읽을 수 있을 때에만 유지한다. 현재 상세도 1줄 줄임표이므로 기존 동작을 완성된 대체 접근 경로라고 가정하지 않는다. 펼친 상세와 현재 준비 단계 이름은 wrap과 자연 높이로 전체 내용을 제공한다. 긴 이름을 화면에 맞추려고 새 저장·입력 제한을 추가하지 않는다.

타이머 숫자·시간 단위·핵심 행동 라벨은 줄임표나 글자 축소로 숨기지 않는다. 부족한 경우 장식 이미지/그래프/빈 간격을 먼저 조정하고 필요한 콘텐츠는 세로 스크롤로 접근하게 한다. 320×568, 2.0배에서 모든 정보를 동시에 노출해야 한다는 뜻은 아니다. 실제 글자 배율을 유지한 채 모든 정보와 핵심 조작에 도달할 수 있어야 한다. 현재 선택된 준비 일정과 A12의 owner/lifecycle 동작을 레이아웃 변경 때문에 초기화하지 않는다.

### 재현 가능한 검증 데이터

- 일정 이름: 정상 짧은 이름, KO 30자, 공백 없는 EN 30자. 실제 생성 길이 제한과 맞춘다.
- 준비 단계·장소: 정상 짧은 이름, KO 100자, 공백 없는 EN 100자. 화면 테스트 fixture이며 새 입력 제한이 아니다.
- 시간: 짧은 값과 여러 자리 timer, 0/양수/지각 상태, 긴 시간 단위. U04의 정확히 정시 계산 오류를 레이아웃에서 덮어쓰지 않는다.
- 행동: 현재 KO/EN 문구 및 여러 줄로 되는 긴 라벨. 테스트 전용 긴 라벨을 쓰면 실제 번역인 것처럼 기록하지 않는다.
- 준비 단계: 대기/현재/완료, 한 단계/여러 단계, skip 표시/미표시, 긴 현재 단계, 준비 완료 후 계속/종료 dialog.
- 홈: 일정 없음/있음, 긴 일정, 달력과 오늘 카드, A12 알림 화면에서 돌아온 실제 홈.
- 상세: 접힘/펼침, 긴 일정과 장소, 시간 정보, 편집 가능한 미래 일정과 상태에 따라 숨는 조작. U01의 삭제 정책 변경을 대신 구현하지 않는다.
- 결과: 일찍/지각 양쪽, 긴 메시지와 큰 시간, 홈 복귀 버튼.

### 자동 검증 매트릭스

| 축 | 값 |
|---|---|
| 논리 viewport | 320×568, 360×640, 390×844, 430×932 |
| locale | KO, EN |
| 글자 배율 | 1.0, 1.3, 2.0 (`TextScaler.linear`로 명시) |
| 폰트 | 실제 번들 Pretendard와 Material Icons를 로드; 테스트 대체 폰트 성공만 사용하지 않음 |
| 안전영역 | 없음, 명시적인 상단·하단 inset 조합. 실제 주입 값을 결과에 기록 |
| 화면 | 홈, 준비 타이머, 결과, 펼친 일정 상세 |

기본 조합 4×2×3 = 24개를 화면별로 실행하고 안전영역 variant도 포함한다. 시나리오마다 실행한 조합과 결과를 기록하여 대표 케이스만 전체 조합 통과처럼 표현하지 않는다. 테스트에서 logical size, DPR, MediaQuery size/inset이 서로 모순되지 않도록 설정한다. 정확한 fixture, clock, viewport, locale, scale, inset은 재현 가능하게 저장한다.

`tester.takeException()`이 null인 것만으로 통과 처리하지 않는다. 텍스트/버튼의 geometry가 다른 필수 정보와 겹치거나 가려지지 않는지 확인하고, 스크롤한 뒤 실제 hit-test 가능한 행동을 탭하여 상태/경로가 예상대로 바뀌는지 확인한다. timer와 반복 애니메이션은 무한 `pumpAndSettle`에 의존하지 않고 고정 clock과 bounded pump를 사용한다. `findsOneWidget`만으로 화면 밖 요소가 사용 가능하다고 간주하지 않는다.

### 모바일 OS 검증

Android와 iOS 각각 최소 한 번 실제 OS 큰 글자 설정에서 핵심 흐름을 수행한다. 기기명·OS 버전·build/source SHA·글자 설정·safe-area·화면 기록/스크린샷과 관측 결과를 남긴다. 모든 자동 viewport 조합을 각각 다른 물리 기기로 재현할 필요는 없다. widget의 linear 2.0배는 OS의 비선형 글자 확대가 실제로 작동하는 증거가 아니다. 기기 접근이 없으면 미실행/device pending으로 남기고 이슈를 닫지 않는다.

## 구현 순서와 의존성

1. **선행 좁은 홈 수정:** 현재 430×932 EN 1.0배 실제 폰트 overflow를 먼저 재현 가능한 회귀로 고정하고 홈 크기 계산/자연 높이를 수정한다. A12 production router의 동일 viewport 알림 진입→준비→홈 복귀도 예외 없이 검증한다. 일반 홈 빈 상태/일정 상태와 기존 compact geometry의 필요한 동작 회귀를 확인한다.
2. **전체 U08:** 원래 P2 우선순위로 돌아가 확정 매트릭스에서 실패를 재현한다. 타이머·단계 목록·결과·상세에 필요한 자연 높이, 줄바꿈, 공간 배분, 스크롤을 적용한다. 확인되지 않은 후보를 이미 고친 것으로 표시하지 않는다.
3. **전체 자동 검증 + 기기 검증:** 동작 테스트·analyzer·관련 CI와 Android/iOS 실제 큰 글자 검증을 각각 기록한다. 좁은 홈 수정의 커밋/테스트 결과와 U08 전체 완료 상태를 분리한다.

선행 A12는 알림 target/owner/준비 시작/복귀 상태의 회귀를 보존해야 한다. U05 현지화와 U04 시간 계산은 독립 이슈다. 현재 문구로 KO/EN 레이아웃을 검증하더라도 현지화 완료라고 주장하지 않으며, 후속 번역 길이 변경은 같은 레이아웃 회귀를 다시 통과해야 한다. U07은 TalkBack/VoiceOver·아이콘 라벨·gesture 대체 동선, T06은 지속적인 접근성/성능 회귀 예산과 landscape/태블릿 전수 범위를 담당한다. 이번 변경에서 화면 회전 지원을 새로 막지 않는다. 이 의존성 분리는 U08의 큰 글자 핵심 행동 접근성 조건을 다른 이슈로 미루는 근거가 아니다.
