# [P1][A03] iOS OnTime Backup 복원 파일 선택기의 UTI 계약 수정

## 문제와 사용자 영향

iOS에서 사용자가 `내 데이터 → 백업 복원`을 선택하고 비밀번호를 입력하면, 파일 선택 화면을 표시하기 전에 `file_selector_ios`가 `ArgumentError`를 던진다. 현재 `XTypeGroup`에는 `.ontimebackup` 확장자와 MIME만 있고 iOS 구현에 필요한 `uniformTypeIdentifiers`가 없기 때문이다. 사용자는 올바른 백업 파일과 비밀번호를 가지고도 복원을 시작할 수 없다.

2026-09-23 감사 **A03**에 대응한다. 판정은 **고정 dependency 구현과 앱 소스에서 실패 경로 확인, 실제 기기 실패 재현 미실행**이다. 코드 수정, 자동 회귀 검사, 실제 iOS 파일 선택 검증을 구분하여 기록한다.

## 제품 용어 및 기존 문서와의 정합성

- **OnTime Backup**: Android와 iOS 사이에 이동할 수 있는 암호화된 로컬 데이터 사본이다.
- **Backup Restore**: 검증된 백업으로 현재 Durable OnTime Data를 명시적으로 교체하는 사용자 동작이다. 병합 import가 아니다.
- **Restore Preview**: 백업 검증이 끝난 뒤 표시하는 복원 내용 및 최종 확인이다. 파일 선택기가 아니다.
- **Backup Freshness**: 현재 설치의 성공한 내보내기에 대한 상태다. 파일 선택이나 복원 시도로 내보내기 성공 상태를 갱신하지 않는다.

CONTEXT의 기존 용어를 사용하므로 glossary 추가는 없다. ADR 0012(비밀번호 암호화), 0013(검증된 복원 교체), 0016(Android/iOS 지원), 0026(플랫폼 공통 형식), 0028(검증된 preview)을 유지한다. iOS picker 계약을 고치는 되돌리기 쉬운 수정이므로 새 ADR는 만들지 않는다. ADR 0028의 전체 staging/validation 구현 완성을 이 작은 수정만으로 주장하지 않는다.

## 합의한 구현 범위

1. iOS 복원 요청에 `uniformTypeIdentifiers: ['public.data']`를 제공한다. 고정 plugin이 지원하는 데이터 파일 선택을 사용해 Android에서 옮긴 `.ontimebackup` 파일의 UTType 인식 차이를 수용한다.
2. Android 및 다른 플랫폼에 기존 `extensions: ['ontimebackup']` / `mimeTypes: ['application/octet-stream']` 필터를 유지한다. iOS를 고치면서 Android 선택 필터를 넓히지 않는다.
3. 파일 확장자와 UTType은 선택 편의를 위한 메타데이터다. 이를 백업의 진위·무결성·호환성 검사로 사용하지 않는다. 파일명 변경만으로 내용을 신뢰하거나 거부하지 않고 기존 암호화 인증·형식 검증 결과를 따른다.
4. `public.data`를 허용한 iOS picker에는 다른 데이터 파일도 표시될 수 있다. 작은 합성 일반 파일·손상 백업·잘못된 비밀번호는 안전하게 실패하고 사용자에게 실패 메시지를 표시한다. 현재 데이터와 Backup Freshness는 유지한다.
5. picker 취소는 null 결과로 처리하며 오류 메시지, 복원 성공 메시지, Restore Preview, DB 쓰기가 발생하지 않는다. 이후 다시 시도할 수 있어야 한다.
6. 선택된 bytes는 기존 `previewEncryptedBackup()` 검증을 통과해야 한다. 검증된 candidate가 생겨도 최종 확인 전에는 데이터를 교체하지 않는다. preview 취소도 DB를 보존한다.
7. 테스트가 실제 iOS UTI 검증을 우회하지 않도록 앱에서 구성한 accepted type groups를 실제 `FileSelectorIOS` 구현에 통과시켜 host API까지 전달된 `public.data`를 확인한다. host API 응답은 fake로 제공하여 파일 선택/취소와 native UI를 분리한다.
8. 별도 platform interface fake로 앱 서비스가 전달한 picker 요청·취소/null·선택 bytes의 preview 전달을 검증한다. 테스트에서 사용하는 전역 플랫폼 등록과 target platform override는 teardown에서 복구한다.
9. 실제 iOS의 local Files provider에서 선택 가능한 파일과 취소 흐름을 확인한다. A02의 모바일 export 결과를 같은 후보 릴리스에서 iOS 복원으로 연결한다.

## 재현 및 기대 동작

### 수정 전 구조적 재현

1. 위 SHA와 lockfile의 앱 type group을 구성한다.
2. 실제 `FileSelectorIOS`를 fake host API와 함께 초기화한다.
3. 앱의 accepted type group으로 `openFile()`을 호출한다.
4. native host 호출에 도달하기 전에 UTI 누락 ArgumentError가 발생함을 확인한다.
5. 실제 기기에서 수행할 경우 `내 데이터 → 백업 복원 → 비밀번호 입력` 이후 파일 선택기가 열리는지 기록한다. 소스 재현을 기기 실행 결과로 대신 적지 않는다.

## 의존 관계 및 제외 범위

- **A02**: 모바일 native export port와 취소/성공/실패 계약. 파일 읽기는 A03, 파일 쓰기는 A02가 소유하며 암호화 서비스와 fixture를 재사용한다. A03 코드 수정은 A02 완료를 기다리지 않고 진행할 수 있으나 export→다른 플랫폼 선택의 통합 증거는 두 작업을 함께 검증한다.
- **D05**: 전체 파일 크기, 레코드·문자열 한도, timezone 등 내용 검증 강화. `public.data` 적용을 파일 안전성 전체 해결로 표현하지 않는다. 이 이슈에서 대용량 임의 파일로 기기를 위험에 빠뜨리는 테스트를 하지 않고 작은 합성 fixture를 사용한다.
- **A09**: 복원 뒤 기존 active/early-start session 및 메모리 상태 정리. picker 수정에 세션 lifecycle 재설계를 섞지 않는다.
- **D02**: 손상 DB의 Recovery Mode에서 백업 복원을 여는 경로. 이 이슈는 정상 실행 중 `내 데이터`의 기존 경로에 한정한다.
- **T01/T02/R02**: 모바일 E2E, native 계약, iOS build CI 확장. A03의 계약 검사를 이후 공통 검사에 편입한다.
- custom UTType 등록, Info.plist의 Files/Open In 앱 연결, 앱 종료 상태에서 외부 파일 열기, 파일 형식 변경, encryption 변경, 자동 클라우드 백업, desktop 제품 지원, picker package 업그레이드는 제외한다.

## 위험 및 완료 판정

`public.data`는 `.ontimebackup`만 보이게 하는 좁은 필터가 아니다. 폭넓은 파일 선택이 portable recovery를 가능하게 하지만 올바른 백업인지는 bytes 검증으로 판단해야 한다. 현재 파일 전체 readAsBytes 경로의 대용량 위험은 D05로 별도 해결한다. 플러그인의 fake host를 통과한 것은 실제 iOS Files provider에서 표시·선택·읽기가 성공했다는 증거가 아니며, simulator 결과도 실제 기기 교차 플랫폼 검증과 구분한다. 저장 공간이나 기기 부족으로 검증하지 못한 부분은 명시하고 이슈를 닫지 않는다.

**답변 1 — root**

> 동의합니다. iOS에서는 public.data로 선택을 허용해 Android 전송 파일의 UTType 인식 차이도 수용합니다. 확장자/UTI를 신뢰 판정에 사용하지 않고 existing crypto/format validation 완료 후만 Restore Preview와 최종 확인을 제공합니다. Android·다른 플랫폼의 기존 extension/MIME 필터는 그대로 두고 custom UTType/Files Open In deep link 등록은 이번 범위에서 제외합니다. 취소는 오류나 DB 변경이 아니며 잘못된 파일/비밀번호는 현재 데이터 그대로 사용자 메시지로 안내해야 합니다. API contract test에서 실제 FileSelectorIOS의 UTI 검증을 우회하지 않게 하고, platform interface fake로 picker request args/취소/null/선택 bytes 전달까지 증명하세요. 실기기 cross-platform 파일 선택은 A02와 묶어 evidence 기록하며 미실행을 완료로 쓰지 않습니다. D05/A09/D02 후속 경계는 scope/dependency에 명시하세요.

**결정**: 위 답변대로 구현·테스트·실기기 완료 경계를 확정했다. 새 glossary/ADR가 필요한 도메인 변경은 없으며, 명확한 plugin 계약 수정에 불필요한 추가 질문을 만들지 않았다. GitHub 이슈 생성·구현·커밋은 root가 수행한다.
