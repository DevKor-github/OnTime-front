## 문제와 결과 목표

소스의 금지 문자열 검사가 통과하고 Android APK가 빌드되어도, 최종 앱에 어떤 SDK와 권한이 포함됐는지, 처음 실행할 때 외부 연결을 요구하는지, 연결 가능한 환경에서 앱이 요청을 시도하는지는 별도 문제다. 현재 검사는 그 증거들을 모두 제공하지 않는다.

R09는 **정확한 release candidate의 정적 구성, 새 설치 오프라인 핵심 여정, 연결 가능한 환경의 앱 자체 네트워크 관측**을 서로 구별해 기록하고 출시 판정에 연결한다. Android·iOS strict local-only, 로그인·서버·원격 analytics 없음이라는 기존 Product Network Boundary를 유지한다. 유한한 관측을 모든 미래 실행에서의 무통신 또는 전체 보안 감사 완료로 표현하지 않는다.

## 공식 근거와 기술적 한계

- Android [apkanalyzer](https://developer.android.com/tools/apkanalyzer)는 실제 APK의 manifest·permission·DEX·파일 구성을 읽는 도구다. 목록은 조사 입력이며 난독화된 모든 SDK와 호출 도달성을 자동 증명하지 않는다.
- Android [Network Inspector](https://developer.android.com/studio/debug/network-profiler)는 지원 네트워크 라이브러리 범위가 제한된다. 그 화면이 비었다는 사실은 Dart/native socket 요청 부재의 증거가 아니다.
- Android [emulator command line](https://developer.android.com/studio/run/emulator-commandline)은 virtual Ethernet packet capture를 설명한다. 실제 사용 도구 버전의 지원 옵션을 확인하고 해당 경로 밖의 loopback/별도 interface·프로세스 귀속 한계를 기록한다. 최신 문서를 이유로 locked toolchain을 임의 교체하지 않는다.
- Apple [packet trace](https://developer.apple.com/documentation/network/recording-a-packet-trace?changes=l_1_6)는 iOS RVI가 기기 전체 네트워크 stack을 나타내며 interface metadata를 구분할 수 있다고 설명한다. 앱 한 개의 trace라는 가정은 금지한다. [troubleshooting](https://developer.apple.com/documentation/network/troubleshooting-packet-traces?changes=_3_7&language=objc)은 capture 손실·local traffic 관측 문제를 검토할 근거다. 검색으로 읽힌 본문 범위를 사용했고 도구 실행 성공을 주장하지 않는다.
- Apple [ATS](https://developer.apple.com/documentation/security/preventing-insecure-network-connections?changes=l_5)는 연결의 보안 조건을 강제하는 기능이다. 안전한 HTTPS와 저수준 API까지 모든 outbound를 차단하는 firewall이 아니다.
- Apple [Entitlements](https://developer.apple.com/documentation/bundleresources/entitlements?language=obj_8)는 최종 서명 시 구성이 결합된다는 근거이며 [distribution entitlement 검사](https://developer.apple.com/library/archive/qa/qa1798/)는 실제 bundle 서명과 profile을 읽는 접근의 근거다. 보관된 Q&A의 플랫폼별 예시 명령을 현 iOS 도구에서 실행했다고 주장하지 않는다.
- Apple [privacy manifest](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files) URL은 확인했으나 직접 open에서 본문은 로드되지 않았다. 이 링크를 API 세부 검증으로 인용하지 않는다. PrivacyInfo의 유무 자체가 network 차단 증거가 아니라는 판정은 기존 ADR0024의 소스·artifact·runtime 구분을 적용한 것이다.

## 확정 계약 1 — 정확한 최종 구성 검사

### Android

1. 실제 후보 AAB의 모든 module manifest와 R04가 그 AAB에서 만든 APK set의 모든 split을 열거한다. base manifest만 읽고 완료하지 않는다. 단독 APK 후보면 실제 단독 APK와 설치 파일의 관계를 확인한다.
2. XML namespace와 permission node 종류를 구조적으로 파싱한다. INTERNET·ACCESS_NETWORK_STATE는 `uses-permission`, SDK 조건부 선언 등 어느 지원 variant에도 없어야 한다. 주석의 문자열을 권한으로 판정하거나 `maxSdkVersion`으로 조건이 붙었다고 금지 권한을 허용하지 않는다. merge source provenance도 기록한다.
3. DEX package/class inventory, native `.so`·assets/config/plugin registrar, Gradle resolved dependency와 Dart lock/도구 입력을 연결한다. Firebase/Auth/analytics/remote HTTP client·server 설정 등 기존 금지 항목은 dormant 상태라도 제거 대상이다.
4. 직접 `HttpClient`/Socket/WebSocket 등의 Dart 호출, native network API와 third-party 자동 초기화·background entrypoint를 조사한다. 생성 문자열/동적 도달성을 좁은 regex만으로 완전히 증명하지 않는다. 분석 불능·미분류 의존성은 pending으로 남겨 수동 근거를 요청하고 자동 allowlist에 추가하지 않는다.
5. release debug transport·VM service용 구성 잔입을 확인한다. source debug/profile 권한을 삭제하는 대신 release에 미포함임을 입증한다. Flutter3.44.4/Dart3.12.2 및 기존 지원 하한을 유지한다.

### iOS

1. 실제 signed IPA를 풀어 main app·포함 extension·embedded framework/동적 라이브러리 및 정적 링크 목록을 확인한다. extension이 없다면 “없음”의 enumeration 증거를 기록한다.
2. 각 실행 bundle의 **effective signed entitlements**, 실제 Info.plist, embedded profile의 필요한 공개 식별자·capability, privacy manifests, plugin 등록·native dependency·SDK 목록을 확인한다. source Runner.entitlements만 검사하지 않는다.
3. 기존 정책과 어긋나는 remote push/auth/CloudKit 등 capability 또는 remote SDK가 있으면 근거와 사용 경로를 확인해 차단한다. time-sensitive/AlarmKit/설치별 secure storage 등 정당한 local 기능을 무조건 금지하지 않는다. 자동 생성 signing 식별자와 민감 provisioning 원문은 구분한다.
4. ATS 예외·Bonjour/local networking·WebView/remote loading·URLSession/Network/CFNetwork 호출 등 조사 대상을 명시한다. 해당 flag가 없다는 이유만으로 outbound가 불가능하다고 하지 않는다. iOS에는 Android INTERNET 제거와 같은 일반 outbound permission 차단을 이 계획에서 가정하지 않는다.
5. engine/OS framework가 제공하는 일반 networking symbol만 발견됐다는 이유로 앱 위반이라 단정하지 않는다. 해당 빌드의 app-owned 호출과 third-party 초기화 도달 경로, 일반 framework 제공 코드의 구별 근거를 기록한다. 반대로 이름을 바꾼 unknown SDK를 안전하다고 추정하지 않는다.

**공통:** inventory에는 artifact 경로/hash, component 이름·버전·origin/lock 관계, 근거 도구, 분류(`allowed_local|prohibited|needs_review`), 판단 이유와 검토 source를 남긴다. 허용 표는 버전/소스별이며 광범위 engine/domain 예외로 변경을 숨기지 않는다. 최종 bytes 안에 폰트·이미지·KO/EN 문구·timezone rules·필수 legal text가 포함되는지 T01의 실제 오프라인 표시 결과와 연결한다.

## 확정 계약 2 — 오프라인 동작과 연결 가능한 runtime 관측

두 실행은 다른 속성을 검증한다. 비행기 모드라 packet이 없다는 사실로 연결 가능한 환경의 자발 송신을 판정하지 않는다.

| 실행 | 사전 조건·행동 | 필수 판정 |
|---|---|---|
| A. Offline Cold Start | 첫 launch 전에 airplane mode, Wi-Fi/cellular 재활성화 없음. warm cache/connected resource download 없는 새 소유 설치. | T01의 동일 exact candidate onboarding·local CRUD·준비/완료·delivery 설정·backup/preview/restore/reset·legal/core resource 여정을 재사용. 네트워크 없이 완료되며 기존 데이터 손상이 없음. |
| B. Connected observation | 별도 새 소유 QA 설치와 연결 가능한 통제된 네트워크, 외부 관측 도구가 시작된 상태에서 첫 launch. | cold start/onboarding/CRUD/준비·로컬 알림/backup preview·restore/reset/background·resume/PID relaunch 동안 app-origin request/attempt와 미분류 flow 확인. |

### 관측 창과 환경 유효성

- 초기 기본값은 앱 실행 전 baseline **60초**, 실제 모든 core 상호작용 구간, background/lock **5분**, resume 및 종료 뒤 각각 **60초**다. 실제 시작/끝과 순서·permission/provider·PID를 기록한다. 시간은 검증 watchdog/관측 범위이며 제품 수명주기 규칙을 바꾸지 않는다. 이보다 늦은 timer/조건부 송신까지 부재라고 주장하지 않는다.
- 관측 전후 별도 known-traffic fixture가 **소유 local controlled sink**로 합성 요청을 보내 capture가 이를 보는지 확인한다. fixture app/process·destination·시각/독립 sink receipt를 제품 trace와 구별한다. fixture를 OnTime binary에 주입하지 않고 외부 공개 endpoint나 사용자 계정으로 보내지 않는다.
- 실제 target ID·OS/patch·모델/ABI·app ID·artifact/signing·capture tool 버전·interface·filter·route/connectivity·positive control·drop counter와 가용 UID/PID attribution을 기록한다. IPv4/IPv6, DNS/TCP/UDP/QUIC, local/loopback 경계를 다룬다. 지원하지 않는 interface/protocol/권한은 명시 사각지대이고 전체를 확인했다고 하지 않는다.
- 잘못된 interface, positive control 미검출, capture 중단/손실, 필수 결과 부재는 `blocked` 또는 `fail`이다. 빈 pcap/0 packets만으로 pass하지 않는다. HTTP proxy 또는 특정 library inspector 하나만으로 우회 경로까지 관측했다고 말하지 않는다.
- 앱이 outbound를 **시도**한 경우 전송이 OS permission/firewall 때문에 막혔어도 위반이다. 다만 패킷이 나오지 않은 denied attempt를 pcap만으로 탐지했다고 주장하지 않는다. 가용 OS 진단·source 도달 경로·실제 외부 trace의 증거 수준을 구별한다. 미확인 시도까지 전부 없었다는 보증은 금지한다.

### 앱·OS·provider 귀속과 false positive

- iOS RVI/device packet trace는 OS와 다른 process의 통신을 함께 포함한다. Android external capture도 IP만으로 앱 UID를 식별했다고 가정하지 않는다. PID/UID·지원되는 process metadata·실제 interaction timeline·component 식별과 독립 기록을 연결한다.
- baseline 통신량을 빼거나 Apple/Google domain을 통째로 allowlist해서 앱 요청을 지우지 않는다. background OS traffic이 보였다는 이유만으로 OnTime 실패라고 단정하지도 않는다. **귀속 불명 traffic은 `unresolved`이며 필요한 runtime 판정은 pending**이다.
- User-Initiated External Navigation이 실제 구현돼 있다면 탭 전 자동 fetch 없음, 명시 OS browser/mail/store 위임, OnTime 데이터가 URL/query에 포함되지 않음을 확인한다. offline destination 실패 후 앱의 데이터·navigation이 보존돼야 한다. browser가 만든 traffic은 근거를 남겨 구분하며 앱 내부 fetch를 browser traffic으로 면제하지 않는다.
- backup export/import의 기본 성공 여정은 local document provider다. 사용자 명시 선택 OS provider의 외부 작업은 위임 이벤트/프로세스·시각으로 구분한다. cloud provider의 원격 동기화 완료는 OnTime의 보장/증거가 아니며 이를 위해 제품 client/permission을 추가하지 않는다. 현재 외부 기능이 없으면 분류기 fixture만 검증하고 실제 제품 여정의 성공으로 바꾸지 않는다.
- 사용자 기기의 raw traffic, 실제 계정/사용자 DB/키/Backup Password를 수집하지 않는다. TLS MITM·사용자 CA 설치·release instrumentation·debug transport 추가로 측정 편의를 확보하지 않는다. 관측에 필요한 권한/귀속 수단이 없으면 제한을 기록하고 OPEN을 유지한다.

## 확정 계약 3 — artifact identity와 CI·기기 역할

| 단계 | 필수 연결 | 한계 |
|---|---|---|
| R04 Android 후보 | exact AAB hash→bundletool/device spec→파생 APK set/각 split hash→실제 설치 identity, 공개 서명 certificate 식별자 | 별도 flutter APK나 test APK의 결과를 후보 AAB에 붙이지 않는다. local validation signing은 Play App Signing이 아니다. |

| PR CI | 기존 source policy + native dependency inventory + 실제 package permission/구성 검사 + parser/gate negative + 소유 emulator/simulator 검증 가능한 행 | unsigned/simulator/disposable key는 물리 signed RC가 아니다. R01은 PR 자동 check를 요구한다. |

receipt의 최소 필드:

- source head/base/실제 checkout 또는 merge SHA, workflow/run/attempt/job, 검증기와 정책 버전, Flutter/Dart/native toolchain·lockfile hashes.
- artifact ID·원본 파일/각 설치 component SHA256·package/bundle ID·version/build·서명종류 및 공개 certificate/서명 식별자, 변환/설치 경로. GitHub archive digest와 내부 AAB/IPA digest를 구별한다.
- 대상/OS/patch/ABI, clean-install 근거, scenario/fixture ID, locale/timezone, provider/permission, 시작/끝·관측 창, expected/actual과 driver/injection.
- static inventory·명시 금지 항목·unknown, capture tool/interface/filter·protocol coverage·drop/control·PID/UID/귀속 근거·unresolved, case별 `pass|fail|blocked|not_run|not_applicable`와 사유.
- evidence 경로/hash, 기존 T01/T02 실행을 재사용하는 정확한 ID, 원 실패와 재실행 관계, 미검증 범위. source나 artifact가 다른 기존 성공은 재사용하지 않는다.

required result 누락·skip/pending·identity 불일치이면 **최종 release gate 미충족**이다. PR 정적 검사 성공과 필수 물리 gate pending을 별도 상태로 유지한다. 같은 이름의 green, latest artifact, branch 이름만으로 후보를 선택하지 않는다. 다운로드 뒤 실제 파일을 재해시하고 receipt·설치 identity를 read-back한다.

### 증거 보관과 데이터 최소화

공개/원격 artifact는 필요한 최소 metadata·합성 fixture 진단·hash·통계·원 실패/후속 결과를 기본30일 보존한다. raw pcap은 기본 게시하지 않는다. 전용 기기여도 OS/provider payload가 포함될 수 있으므로 검토에 꼭 필요하면 소유 로컬 제한 보관 후 정리하고 요약과 원본 hash의 관계만 남긴다. 키·비밀번호·서명 private key·production DB·개인 식별 provisioning 원문·사용자 payload는 저장소/CI artifact/cache에 넣지 않는다. redaction 전 원본을 공개한 뒤 삭제하는 방식은 사용하지 않는다.

새 disposable AVD/simulator 및 명시 지정 QA 물리 기기만 사용한다. 기존 simulator `C8BA159D-A97A-458B-A5FC-B04A8B6F2848`, 사용자 설치, 다른 작업의 target/호스트 네트워크는 변경하지 않는다. target을 자동으로 첫 연결 기기로 선택하지 않는다. 문서 작성 시 기기/서명 가용성은 새로 조회하지 않았으며 실행 직전 확인한다.

## 구현 순서와 구체 검증 행렬

1. 기존 source/notification 검사와 R04/R08 identity schema를 고정한다. R02/T01/T02 제공 entrypoint·기기·서명 가용성을 확인하고 dependency pending을 드러낸다.
2. 실제 APK/AAB module/split, signed IPA/app/extension의 구성 inventory와 parser를 구현한다. source/lock/native 의존성 및 최종 구성의 차이를 출력하고 unknown을 차단한다.
3. 검사기 fixture와 실제 package 입력을 연결한다. 기존 source scan은 강화하되 새로운 문자열 규칙을 완전한 도달성 분석으로 부르지 않는다.
4. 외부 관측·target isolation·positive control·귀속/결과 schema를 만들고 전용 known-traffic fixture로 탐지 가능성을 실제 한 번 검증한다. 제품 binary에는 송신코드를 추가하지 않는다.
5. 같은 candidate의 T01 offline 여정을 재사용하고 연결 가능한 별도 설치를 측정한다. emulator/simulator 조기 검사 후 물리 양 플랫폼 RC를 수행한다.
6. 원격 artifact 다운로드/hash·같은 소스/설치 identity·필수 행 완전성을 확인하고 R01/R04/O02/R08에 receipt를 연결한다. 사각지대·unresolved·환경 실패가 남으면 완료로 닫지 않는다.

### Q1 — strict boundary의 판정 범위

**Agent:**
